# MyPaas Server Architecture and Workflow

## Overview

The **server component** of MyPaas (`mypaas.server`) is the core infrastructure that runs on your VM or bare metal server. It provides the foundation for hosting multiple applications with automatic HTTPS, load balancing, monitoring, and secure deployments.

This document explains how the server part works, its architecture, and the workflow from initialization to deployment.

---

## Core Responsibilities

The server component handles:

1. **Server Initialization** - Setting up the PaaS environment
2. **Traefik Configuration** - Reverse proxy with automatic HTTPS
3. **Container Management** - Docker-based application deployment
4. **Authentication** - Secure key-based access control
5. **Statistics & Monitoring** - System and application metrics
6. **Daemon Management** - Background service for API communication
7. **Scheduled Operations** - Automated reboots and maintenance

## Initialization Process (`_init.py`)

### `init()` Function
The entry point for setting up a new PaaS server. Performs the following steps:

1. **Collects Configuration Information:**
   - Admin domain (e.g., `admin.mydomain.com`)
   - Dashboard username and password (stored as Apache-style hash)
   - Email for Let's Encrypt certificates (optional)

2. **Prepares the System:**
   - Creates `~/_mypaas/` directory for configuration and data
   - Saves configuration to `~/_mypaas/config.toml`
   - Creates `~/_mypaas/authorized_keys` file for public keys

3. **Sets Up Infrastructure:**
   - Creates Docker network `mypaas-net` for container communication
   - Initializes Traefik router with proper configuration

4. **Output:** Server is ready, user must run `mypaas server restart all` to start

### `restart()` Function
Manages the lifecycle of core PaaS processes:
- `all` - Restarts router, stats server, and daemon
- `daemon` - Restarts the deploy daemon (systemctl service)
- `router` - Restarts Traefik router (Docker container)
- `stats` - Restarts statistics server (Docker container)

## Authentication System (`_auth.py`)

### Key Management
- **Storage:** Public keys stored in `~/_mypaas/authorized_keys`
- **Format:** One key per line, comments allowed with `#`
- **Caching:** Keys are cached for 5 seconds to prevent filesystem attacks
- **Lookup:** `get_public_key(fingerprint)` retrieves keys by their fingerprint

### Configuration Management
- **File:** `~/_mypaas/config.toml`
- **Structure:** TOML format with `init` and `env` sections
- **Functions:**
  - `load_config()` - Loads configuration from disk
  - `save_config(config)` - Saves configuration to disk

### Security Features
- Password hashing using OpenSSL's APR1 algorithm
- Rate-limited key file reading (max once every 5 seconds)
- Secure file permissions (e.g., `acme.json` set to 0600)

## Traefik Reverse Proxy (`_traefik.py`)

### Architecture
Traefik is the core reverse proxy that handles:
- **HTTPS Termination** - Automatic SSL/TLS certificates via Let's Encrypt
- **Load Balancing** - Distributes traffic across multiple containers
- **Dynamic Configuration** - Auto-discovers Docker containers via labels
- **Dashboard** - Web interface for monitoring

### Configuration Files

#### 1. `~/_mypaas/traefik.toml` (Main Configuration)
Generated by `init_router()` with:
- **Entry Points:** Port 80 (web) and 443 (web-secure)
- **Providers:** Docker socket and file-based configuration
- **Let's Encrypt:** Automatic certificate resolution with HTTP challenge
- **Metrics:** InfluxDB protocol for statistics
- **Logging:** Set to WARN level

#### 2. `~/_mypaas/staticroutes.toml` (Static Routes)
Generated by `init_router()` with:
- **Traefik Dashboard:** Accessible at `/dashboard` or `/api`
- **MyPaas Daemon:** Routes `/daemon` to localhost:88
- **Middleware:**
  - `auth` - Basic authentication for dashboard
  - `https-redirect` - Redirects HTTP to HTTPS
  - `hsts-header` - Adds security headers
- **TLS Options:** Intermediate security profile with modern cipher suites

#### 3. `~/_mypaas/acme.json` (Certificates)
- Stores Let's Encrypt certificates
- Created with 0600 permissions for security
- Persists across Traefik restarts

### `restart_router()` Function
1. Pulls the specified Traefik Docker image
2. Stops and removes existing Traefik container
3. Launches new container with proper configuration:
   - Host network mode for port 80/443
   - Docker socket mount for container discovery
   - Configuration files mounted as volumes
   - Environment variables for service identification

### `init_router()` Function
1. Creates `acme.json` with proper permissions
2. Generates `traefik.toml` with email configuration
3. Generates `staticroutes.toml` with domain and credentials

## Deployment Engine (`_deploy.py`)

### Overview
The deployment engine is the heart of MyPaas. It:
- Parses Dockerfiles with special `mypaas.*` comments
- Builds Docker images
- Creates and manages containers with proper labels
- Handles scaling, health checks, and zero-downtime deployments

### Dockerfile Configuration
Applications are configured using special comments in the Dockerfile:

```dockerfile
# mypaas.service=myapp           # Service name (required)
# mypaas.url=https://myapp.com   # URL to serve
# mypaas.port=8080              # Container port
# mypaas.publish=80:8080        # Port mapping on host
# mypaas.volume=/host:/container # Volume mapping
# mypaas.scale=3                # Number of containers
# mypaas.scale=3 roll           # Scaling with rolling deployment
# mypaas.healthcheck=/health 10s 5s  # Health check path, interval, timeout
# mypaas.env=KEY=value          # Environment variable
# mypaas.env=SECRET_KEY         # Reference to config.toml env section
# mypaas.maxcpu=1.5             # CPU limit
# mypaas.maxmem=512m            # Memory limit
```

### Deployment Process

#### 1. Configuration Parsing
The `get_deploy_generator()` function:
- Reads the Dockerfile
- Extracts all `mypaas.*` configuration directives
- Validates configuration values
- Sets defaults (port=80, scale=None, etc.)

#### 2. Container Preparation
- **Image Building:** Builds Docker image with `--pull` if using `:latest`
- **Name Cleaning:** Ensures service names are valid Docker identifiers
- **Label Generation:** Creates Traefik-compatible labels for routing

#### 3. Traefik Label Generation
For each URL, generates labels for:
- **Router Rules:** Host and path-based routing
- **Entry Points:** web (HTTP) or web-secure (HTTPS)
- **TLS Configuration:** Certificate resolver and options
- **Middleware:** HTTPS redirect, HSTS headers, authentication
- **Load Balancer:** Server port, health checks

#### 4. Deployment Strategies

##### No Scaling (`_deploy_no_scale`)
For single-container deployments:
1. Build new image
2. Rename old containers (with unique timestamp)
3. Stop old containers
4. Start new container
5. Remove old containers
6. Prune unused containers and images

##### Safe Scaling (`_deploy_scale_safe`)
For multi-container deployments with zero downtime:
1. Build new image
2. Rename all old containers
3. Stop all old containers
4. Start all new containers simultaneously
5. Remove old containers
6. Prune resources

##### Rolling Scaling (`_deploy_scale_roll`)
For multi-container deployments with gradual rollout:
1. Build new image
2. Rename all old containers
3. For each new container:
   - Start new container
   - Wait calculated pause time
   - Stop corresponding old container
4. Remove remaining old containers
5. Prune resources

The rolling deployment calculates pause times based on expected boot time to ensure at least one old container remains available during the transition.

#### 5. Container Management
- **Network:** All containers use `mypaas-net` network
- **Restart Policy:** `--restart=always` for automatic recovery
- **Resource Limits:** CPU and memory limits applied if specified
- **Volume Mounts:** Host directories mounted into containers
- **Environment Variables:** Service-specific and user-defined variables

### Helper Functions
- `get_containers_info(service_name)` - Gets info on all running containers
- `get_id_name_for_this_service(container_infos)` - Filters containers for a specific service
- `clean_name(name, allowed_chars)` - Sanitizes names for Docker compatibility

## Daemon Management (`_daemon.py`)

### Overview
The MyPaas daemon (`mypaas.daemon`) runs as a systemd service and provides the API for client-server communication.

### `restart_daemon()` Function
1. **Creates systemd service file** at `/etc/systemd/system/mypaasd.service`
2. **Service Configuration:**
   - Runs as root
   - Uses Python 3
   - Executes `python3 -m mypaas.daemon`
   - Automatic restart on failure
   - 2-second delay between restarts
3. **Systemd Commands:**
   - `daemon-reload` - Reloads systemd configuration
   - `restart mypaasd` - Restarts the service
   - `enable mypaasd` - Enables auto-start on boot

### Service File Content
```ini
[Unit]
Description=MyPaas daemon
After=network.target
StartLimitIntervalSec=0

[Service]
Type=simple
Restart=always
User=root
WorkingDirectory=/root
ExecStart=/usr/bin/python3 -m mypaas.daemon
RestartSec=2
Environment=MYPAAS_SERVICE=daemon
Environment=MYPAAS_CONTAINER=daemon

[Install]
WantedBy=multi-user.target
```

## Statistics Server (`_stats.py`)

### Overview
The statistics server collects and serves system and application metrics.

### `restart_stats()` Function
1. **Loads Configuration:** Reads domain from `~/_mypaas/config.toml`
2. **Prepares Deployment Directory:** Creates temporary directory at `~/_mypaas/stats_deploy_cache`
3. **Generates Dockerfile:** Creates a specialized Dockerfile for the stats service
4. **Copies Stats Library:** Copies `mypaas/stats/` directory into deploy directory
5. **Deploys:** Uses the standard deployment engine
6. **Cleans Up:** Removes temporary deployment directory

### Stats Service Dockerfile
```dockerfile
# mypaas.service=stats
# mypaas.url=https://PAAS_DOMAIN/
# mypaas.port=80
# mypaas.publish=127.0.0.1:8125:8125/udp
# mypaas.volume=/root/_stats:/root/_stats
# mypaas.scale=0

FROM ubuntu:20.04
# ... (installs Python dependencies)
WORKDIR /root
COPY . .
CMD ["python3", "-m", "stats"]
```

### Key Features
- **UDP Port:** 8125 for metrics collection (InfluxDB protocol)
- **Volume:** Persistent storage at `/root/_stats`
- **No Scaling:** Runs as single container (`scale=0` means no scaling)
- **Protected:** Behind authentication middleware

## Scheduled Reboot (`_reboot.py`)

### Overview
Provides automated server reboot functionality for maintenance.

### `schedule_reboot()` Function
1. **Creates systemd timer** at `/etc/systemd/system/mypaas_reboot.timer`
2. **Creates systemd service** at `/etc/systemd/system/mypaas_reboot.service`
3. **Reloads systemd** and enables the timer

### Default Schedule
- **When:** `Sun 06:00:00` (every Sunday at 6 AM)
- **Customizable:** Any systemd calendar specification

### Timer Configuration
```ini
[Unit]
Description=MyPaas reboot timer

[Timer]
OnCalendar=WHEN

[Install]
WantedBy=timers.target
```

### Service Configuration
```ini
[Unit]
Description=MyPaas reboot service

[Service]
User=root
ExecStart=/bin/bash -c 'reboot now'
RestartSec=20
```

## Utility Functions (`mypaas.utils`)

### `dockercall(*args, fail_ok=False)`
The primary interface for executing Docker commands:
- Constructs command: `docker` + arguments
- Executes via subprocess
- Returns decoded output
- Raises RuntimeError on failure (unless `fail_ok=True`)
- Adds helpful error context

### Other Utilities
- `input_ask_bool()` - Yes/no user input
- `input_ask_int()` - Numeric user input with validation
- `generate_uid()` - Random string generation
- `PublicKey`, `PrivateKey` - Cryptographic key management

## Workflow Summary

### 1. Initial Setup
```bash
mypaas server init
# User provides: domain, username, password, email
# System creates: config, keys, Docker network, Traefik config

mypaas server restart all
# Starts: Traefik, daemon, stats server
```

### 2. Application Deployment
```bash
# Client side
mypaas push
# 1. Reads Dockerfile with mypaas.* comments
# 2. Builds Docker image
# 3. Pushes to server via daemon API

# Server side (automatic)
# 1. Receives deployment request
# 2. Parses configuration from Dockerfile
# 3. Builds/updates Docker image
# 4. Creates/updates containers with Traefik labels
# 5. Manages scaling and health checks
# 6. Handles zero-downtime transitions
```

### 3. Ongoing Management
```bash
# Restart components
mypaas server restart router    # Update Traefik config
mypaas server restart daemon    # Restart API service
mypaas server restart stats     # Restart monitoring

# Schedule maintenance
mypaas server schedule-reboot   # Set up weekly reboots

# Deploy from server
mypaas server deploy /path/to/app  # Local deployment
```

## Security Features

### 1. Authentication
- **RSA Key Pairs:** Client-server communication uses public/private keys
- **Authorized Keys:** Server maintains list of approved client public keys
- **Dashboard Protection:** Basic auth with hashed passwords

### 2. Network Security
- **HTTPS Everywhere:** Automatic Let's Encrypt certificates
- **HSTS Headers:** Enforces HTTPS usage
- **Modern TLS:** Intermediate security profile with strong cipher suites
- **No Direct Access:** Daemon listens only on localhost:88

### 3. Container Security
- **User Namespaces:** Containers run with proper user context
- **Volume Restrictions:** Cannot mount sensitive directories (`~/.ssh`, `~/_mypaas`)
- **Resource Limits:** CPU and memory constraints prevent resource exhaustion
- **Network Isolation:** All containers on dedicated `mypaas-net` network

### 4. Filesystem Security
- **Secure Permissions:** Certificate files (acme.json) have 0600 permissions
- **Configuration Isolation:** All config in `~/_mypaas/` directory
- **Rate Limiting:** Key file reading limited to prevent DoS

---

## Performance Considerations

### 1. Deployment Strategies
- **Rolling Deployments:** Minimizes downtime for scaled services
- **Safe Deployments:** Faster for services that can tolerate brief downtime
- **No Scale:** Simple and fast for single-container services

### 2. Resource Management
- **CPU Limits:** Prevents any single service from consuming all CPU
- **Memory Limits:** Prevents memory exhaustion
- **Automatic Pruning:** Removes unused containers and images

### 3. Caching
- **Key Caching:** Public keys cached for 5 seconds
- **Docker Layer Caching:** Builds reuse cached layers when possible

---

## Error Handling and Recovery

### 1. Deployment Failures
- **Automatic Rollback:** If deployment fails, old containers are restored
- **Container Recovery:** `--restart=always` ensures containers restart on crash
- **Health Checks:** Traefik only routes to healthy containers

### 2. System Failures
- **Daemon Auto-Restart:** systemd automatically restarts crashed daemon
- **Traefik Auto-Restart:** Docker automatically restarts crashed router
- **Stats Persistence:** Statistics data persists across restarts

### 3. User Recovery
- **Manual Restart:** `mypaas server restart` commands for troubleshooting
- **Configuration Backup:** Config files are preserved during updates
- **Container Inspection:** Docker commands can inspect running containers

## Best Practices

### 1. Server Setup
- Use a dedicated domain for the PaaS admin interface
- Set up DNS records before running `init`
- Use strong passwords for the dashboard
- Consider using a non-root user with sudo privileges

### 2. Application Deployment
- Always specify `mypaas.service` in Dockerfile
- Use `mypaas.url` for each domain/subdomain
- Set appropriate resource limits (`maxcpu`, `maxmem`)
- Use health checks for production services
- Test deployments with `scale=1` before scaling up

### 3. Maintenance
- Monitor system resources regularly
- Update Traefik version by updating MyPaas
- Backup `~/_mypaas/` directory regularly
- Test reboot process before relying on scheduled reboots

### 4. Security
- Rotate client keys periodically
- Update dashboard credentials regularly
- Monitor `~/_mypaas/authorized_keys` for unauthorized keys
- Keep Docker and system packages updated
- Use firewall to restrict access to ports 80/443 only

## Troubleshooting

### Common Issues

1. **Traefik not starting:**
   - Check Docker logs: `docker logs traefik`
   - Verify domain DNS resolution
   - Check certificate permissions: `ls -la ~/_mypaas/acme.json`

2. **Deployment failing:**
   - Check Dockerfile syntax
   - Verify `mypaas.service` is specified
   - Check for port conflicts
   - Review container logs: `docker logs <container>`

3. **Daemon not responding:**
   - Check service status: `systemctl status mypaasd`
   - View logs: `journalctl -u mypaasd`
   - Restart: `mypaas server restart daemon`

4. **HTTPS not working:**
   - Verify DNS points to server IP
   - Check Let's Encrypt rate limits
   - Test with `curl -v https://yourdomain.com`

### Debug Commands

```bash
# View all containers
docker ps -a

# View container logs
docker logs <container_name>

# View Traefik dashboard
# Access: https://your-domain.com/dashboard

# Check daemon status
systemctl status mypaasd

# View daemon logs
journalctl -u mypaasd -f

# Check configuration
cat ~/_mypaas/config.toml
cat ~/_mypaas/traefik.toml

# Test deployment manually
mypaas server deploy /path/to/app
```

## Summary

The MyPaas server component provides a complete, self-hosted PaaS solution built on Docker and Traefik. Its architecture is designed for:

- **Simplicity:** Easy setup and configuration
- **Security:** Automatic HTTPS, authentication, and isolation
- **Reliability:** Automatic restarts, health checks, and rollback
- **Scalability:** Support for multiple containers and rolling deployments
- **Monitoring:** Built-in statistics and dashboard

The server workflow follows a clear pattern: initialize → configure → deploy → monitor → maintain. Each component (Traefik, daemon, stats) runs in its own container or service, communicating through well-defined interfaces (Docker labels, HTTP API, systemd).

This architecture allows MyPaas to provide enterprise-grade features while maintaining the simplicity of a self-hosted solution.
